## 可以做什么？

- **PMX 转人物包**：生成 HUM、O3D 模型、PNG 贴图和转换报告。
- **自动命名**：使用 PMX 文件名生成角色标识，中文自动转为拼音，也可手动调整。
- **自动估算高度**：从模型网格读取高度并按惯用比例换算，支持手动设置。
- **统一保存导出结果**：GUI 将人物包存入 OMSI 内容目录下的 `omsipmxtool_exports`，同名自动编号，不覆盖旧包。
- **自动安装**：将完整人物包安装到游戏的 `Humans` 目录。
- **一键应用司机**：更新全部已安装地图的司机列表，让支持动态司机的车辆使用所选角色。
- **备份与恢复**：保存原始司机列表，支持恢复，并在检测到外部修改时停止覆盖。
- **展示模型说明**：导入时展示 PMX 内嵌说明，滚动到底后才可继续；没有内嵌说明则不弹窗。

## 使用流程

1. 选择 OMSI 内容目录，其中应包含 `maps` 和 `Vehicles`。
2. 选择 PMX 文件，并保留模型目录中的配套贴图。
3. 阅读模型内嵌说明，检查角色标识和模型高度。
4. 点击 **生成人物包**，按需自动安装。
5. 在 **角色库与游戏** 中选择角色，点击 **一键应用全部车辆（全部地图）**。
6. 完全重启 OpenOMSI，在支持动态司机的车辆中检查显示效果。

需要恢复时，使用 **恢复原司机**。新增地图后，需要再次应用。

> “一键应用”通过地图司机列表生效，不替换车辆自带的固定人物模型；AI 车辆也可能使用该角色。

## 详细使用说明

### 1. 准备软件、游戏和模型

Windows 用户可从 [Release](https://github.com/splDANHENG/omsipmxtool/releases/tag/v0.3.2) 下载 `omsipmxtool-0.3.2-windows-x64.zip`，完整解压到可写目录，双击 `omsipmxtool.exe`。不要只移动 EXE，也不要在压缩包内直接运行。当前在 Windows 10 x64 上验证，Windows 11 尚未完成实机验证。

如果希望从源码运行，在 GitHub 点击 **Code → Download ZIP**，完整解压后按下方“从源码运行”安装并启动；也可使用 Git 克隆：

```bash
git clone https://github.com/splDANHENG/omsipmxtool.git
cd omsipmxtool
```

另行准备可正常运行的 OpenOMSI、合法取得的 OMSI 2 游戏内容，以及许可允许相关使用的 PMX 模型。建议先用原版司机进入一次目标地图和车辆，确认游戏本身正常。

完整解压模型配布包，保留 `.pmx` 与贴图的相对位置；不要只复制一个 PMX 文件。贴图应位于 PMX 所在目录或其子目录，当前不支持引用模型目录以外的贴图。不要将未经许可的模型放进本项目仓库提交。

### 2. 首次启动与版权提示

第一次启动图形界面时，会显示项目版权与使用说明。滚动到末尾，点击 **继续** 进入；无需勾选复选框，关闭提示或选择退出则不进入软件。

阅读记录保存在本机用户数据目录，后续启动通常不再提示；说明内容更新后会重新提示。项目提示不替代原模型许可，导入含内嵌说明的 PMX 时还会单独显示模型原文。

### 3. 选择 OMSI 内容目录

在 **PMX 转换 → OMSI 目录 → 选择目录** 中，选择同时包含 `maps` 和 `Vehicles` 的内容根目录，例如你的 OMSI 2 安装目录。

不要选择 `Vehicles` 子目录、某辆车的文件夹，或只有 `openomsi.exe` 的程序目录。如果 OpenOMSI 使用了独立内容目录，请确保本工具所选目录就是游戏实际加载地图和司机列表的位置。

GUI 无论是否勾选自动安装，都需要有效的 OMSI 内容目录，因为导出结果会统一保存在这里。只想在任意位置离线转换时，可使用下方命令行方式。

### 4. 导入 PMX 并检查设置

点击 **选择 PMX**，阅读模型内嵌说明后继续。没有内嵌说明时不弹窗，但仍应自行阅读配布页面及随附 Readme。

- **角色标识**：默认来自 PMX 文件名，中文转无声调拼音。例如 `饮月君 1708.pmx` 生成 `yinyuejun_1708`。可以手动修改，多音字需要自行校正。
- **模型总高度**：默认从完整网格范围估算。头发、帽子和饰品也会计入，不一定等于角色设定身高。估算超出 0.5–3 米会停止自动转换；取消自动估算后可手动填写。
- **骨骼映射**：一般先留空。提示某个关节缺失或存在多个候选时，点击 **检查模型与骨骼** 查看准确名称，再提供 JSON 映射。
  普通腿骨与唯一对应的 D 腿变形骨初始位置不一致时，会自动选择 D 骨；手动指定的映射仍优先使用。
  点击 **图形化编辑** 可查看每个关节的自动识别结果，搜索并选择模型骨骼，点击 **应用** 后直接用于转换，无需手写 JSON。窗口支持加载 / 保存 JSON 和全部恢复自动；切换 PMX 会清除当前映射。
  左侧提供模型灰模和骨骼预览：左键拖动旋转、滚轮缩放、右键拖动平移。点击右侧关节按钮可高亮当前映射；选择映射目标后点击模型骨骼，再点击 **将选中骨骼映射到当前关节**。重叠骨骼可在候选列表中切换，黄色表示选中骨骼，橙色表示 D 腿骨。预览不加载贴图、不模拟动画与物理，连线表示骨骼父子关系；修改仅用于转换映射，不改写原 PMX。
- **统一导出目录**：自动生成，不可直接编辑。同名导出会追加 `_2`、`_3`，不会覆盖已有包。

检查结果和错误详情会显示在页面下方。遇到骨骼错误时不要随意把多个关节映射到同一骨骼；可以参考后文的映射示例或提交 Issue。

### 5. 生成人物包与自动安装

点击 **生成人物包**，等待转换结束。转换期间不要强制关闭程序。

默认勾选 **转换后自动安装到 OMSI**：完成转换后，将人物加入角色库并复制到游戏使用的目录。取消勾选后仍会生成导出包并加入角色库，但不自动复制到游戏 `Humans` 目录。

典型导出结构如下，其中 `MyDriver` 是本次角色标识：

```text
OMSI 内容目录/
└─ omsipmxtool_exports/
   └─ MyDriver/
      ├─ Humans/
      │  └─ MyDriver/
      │     ├─ driver.hum
      │     ├─ model/       # 模型配置和 O3D 网格
      │     └─ texture/     # PNG 贴图
      ├─ conversion-report.json
      └─ INSTALL.txt
```

自动安装的副本位于 `Humans/OMSIMod_<角色ID>/`。该名称用于区分角色，不需要手动修改。

若提示“人物包已生成，但安装／入库未完成”，导出包仍会保留。先查看下方错误，处理路径、权限或贴图问题后，再在角色库中导入导出包里的 `driver.hum`，并尝试应用。不要因为安装失败就删除原模型或游戏备份。

### 6. 应用到游戏

先退出正在运行的游戏，再进入 **角色库与游戏** 标签页：

1. 选中需要使用的角色。
2. 确认 OMSI 内容目录，点击 **保存路径并扫描地图 / 车辆**。
3. 点击 **一键应用全部车辆（全部地图）**。
4. 查看下方结果，确认成功、失败及跳过的地图；批量结束不代表每张地图都成功。
5. 从平时使用的游戏启动器启动 OpenOMSI，进入已成功应用的地图和支持动态司机的车辆。

一键应用按钮始终处理当前内容目录中的全部已安装地图，不受单地图复选框影响。如果只想应用一张地图，取消勾选 **应用 / 恢复全部已安装地图**，选择地图，再点击 **应用所选角色**。

此操作会备份并更新各地图的 `drivers.txt`，把所选人物放在列表首位，保留其他条目。它不会把车辆自带的固定司机网格替换掉，也不保证所有车辆都能显示人物。新增地图后需再次应用。

**游戏程序** 一栏仅供“启动所选地图 / 车辆（可选）”快捷功能使用。可以正常从自己的启动器进入游戏，不必通过本工具启动。

### 7. 导入已有 HUM、重新转换与恢复

- **已有 HUM 人物包**：点击 **导入 HUM**，选择完整独立人物目录中的 `.hum`。模型配置、O3D 和贴图需要随包保留，当前不支持跨人物目录引用资源。
- **重新转换同一模型**：再次生成新包，并应用角色库中的新条目。程序不会自动替换旧条目所对应的已安装文件。
- **恢复原司机**：按需要选择全部地图或单张地图，点击 **恢复原司机**。仅恢复本工具有备份、且未检测到外部修改冲突的列表；没有备份的地图会跳过。
- **移出角色库**：只删除列表记录，不删除源包、安装副本或恢复记录，也不等同于恢复地图司机。

恢复操作会保留已安装人物，以免破坏其他地图的引用。不要在未确认引用关系前手动删除 `Humans/OMSIMod_<角色ID>`。

如果提示“司机列表已被外部修改”，请先保留现状和备份，核对是否被其他 Mod、游戏更新或手工编辑改变。不要删除备份来强行绕过保护。

### 8. 常见问题

| 现象 | 建议检查 |
| --- | --- |
| 找不到地图或无法选择内容目录 | 是否选中了包含 `maps` 和 `Vehicles` 的根目录，且与 OpenOMSI 实际内容路径一致。 |
| 缺少贴图或人物目录以外的资源 | 是否完整解压模型，是否移动了贴图，是否存在跨目录引用。 |
| 骨骼识别失败 | 查看检查结果和准确骨骼名，按关节提供映射；不要只改文件名反复尝试。 |
| 自动高度异常 | 是否有远离主体的网格或非标准单位；取消自动估算并手动设置。 |
| 外部视角没有司机 | 确认应用成功、完全重启、地图正确、车辆支持动态司机，并检查 OpenOMSI 的司机显示设置。 |
| 外部可见，但驾驶位没有手臂 | 按下一节开启驾驶视角手臂显示；第一人称不会显示完整身体。 |
| 换角色后仍显示旧角色 | 确认选择了新导出的角色条目，应用到了实际地图，并完全重启游戏。 |
| 袖摆挡住仪表盘或频繁穿模 | 当前不还原服装物理；参考“选择角色的小建议”，换用装饰较少的模型。 |
| 新版游戏中出现异常或 N 挡手臂乱动 | 对比旧版本及原版司机，再按“已知问题与反馈”提供复现信息。 |

## 在驾驶视角显示司机手臂

OpenOMSI 支持在第一人称驾驶视角中显示司机的手部和手臂。这是游戏自身的显示选项，需要在 OpenOMSI 中开启。

1. 打开 OpenOMSI 启动器的 **Settings（设置）→ Camera（相机）**。
2. 开启 **Driver's hands in the cab view**（驾驶室视角显示司机双手；中文翻译可能随版本不同）。
3. 进入游戏并切换到驾驶视角，默认按键为 **F1**。已进入游戏时，也可从 **Esc → Options（选项）→ Camera（相机）** 查找该选项。

如果界面中找不到选项，可在完全退出游戏和启动器后，备份并编辑 OpenOMSI 的 `settings.cfg`：

- Windows：`%USERPROFILE%\.openomsi\settings.cfg`
- macOS / Linux：`~/.openomsi/settings.cfg`

找到并修改对应条目；不存在时新增一行，不要覆盖其他设置：

```ini
hands_in_cab=1
```

保存后重新启动 OpenOMSI。关闭该功能时设为 `hands_in_cab=0`。

此方式已核对 OpenOMSI 0.3.33 与 2026-10-18 查阅的上游设置源码；其他版本的界面位置可能变化。第一人称显示会隐藏部分身体，不等同于外部视角中的完整人物。手部贴合效果仍取决于车辆、模型和游戏动作逻辑。

参考：[OpenOMSI 设置定义](https://github.com/openOMSI-org/openOMSI/blob/741e1bc9363479315aaa1cdfb6bf21839b4735ee/launcher/ui/js/pages/settings-schema.js)、[配置读取实现](https://github.com/openOMSI-org/openOMSI/blob/741e1bc9363479315aaa1cdfb6bf21839b4735ee/crates/omsi-app/src/settings.rs)、[官方使用指南](https://github.com/openOMSI-org/openOMSI/blob/main/docs/USER_GUIDE.md)。

## 模型支持与限制

支持读取 PMX 2.0 / 2.1 的几何、材质和骨骼，并将权重归并到目标人体骨架。支持常见日文、英文骨骼名称，以及部分模型使用的 D 腿变形链；识别失败时可提供自定义骨骼映射。

当前仍有这些限制：

- 不保留 MMD 表情、物理模拟、IK、动态衣服及独立手指动作。
- SDEF、QDEF 权重采用线性蒙皮近似处理。
- Toon、球面反射、描边等效果不会完整还原。
- 自动高度按完整网格 Y 轴范围乘 `0.08` 估算，包含头发和饰品，不保证等于真实身高；非标准比例模型需手动调整。
- 复杂姿态、服装和头发可能出现变形或穿模，坐姿及方向盘贴合仍需游戏内检查。
- 仅省略默认材质透明度为零的部分，不按角色、厂商或材质名称删除几何。

**转换成功表示文件已生成，不代表所有车辆和场景下都显示正常。**

### 选择角色的小建议

受当前 OpenOMSI 人物系统及本工具转换能力的限制，暂时难以还原角色服装、飘带和挂饰的物理效果。这些部件可能随简化后的骨骼一起运动，无法像原模型那样自然摆动或避让。

**除非是真爱，建议尽量避开带有宽大袖摆、垂袖，或袖口、手臂上带有较长飘带及挂饰的模型。** 例如饮月君、枫原万叶、魈、刻晴等角色的部分造型，需要特别留意这些部件；具体情况以所选模型为准，并非这些角色都无法使用。

这类部件在转动方向盘或执行司机动作时，可能遮挡仪表盘、伸入视野，并与方向盘、驾驶台或身体频繁穿模。若更看重驾驶时的视野与稳定效果，优先选择袖口收紧、手臂附近装饰较少的模型。

## 从源码运行

需要 Python 3.10 或更新版本。请在项目目录中执行：

```powershell
# Windows
py -3 -m venv .venv-gui
.\.venv-gui\Scripts\python.exe -m pip install ".[gui]"
.\.venv-gui\Scripts\python.exe -m omsimod.gui
```

```bash
# macOS / Linux
python3 -m venv .venv-gui
.venv-gui/bin/python -m pip install '.[gui]'
.venv-gui/bin/python -m omsimod.gui
```

不同系统的支持情况取决于 Python、Qt 和依赖版本。本次源码审查在 Windows 完成，其他系统仍需对应环境验证。

### macOS 使用方式（终端启动图形界面）

macOS 可从源码运行，无需先打包成 `.app`。终端用于安装依赖和启动程序；启动后仍使用图形界面操作，不能直接运行 Windows 发布包中的 `.exe`。

1. 安装 Python 3.10 或更新版本，可从 [Python 官网](https://www.python.org/downloads/macos/) 获取适用于当前系统的安装程序。在“终端”运行 `python3 --version` 确认版本。
2. 从本仓库的 **Code → Download ZIP** 下载源码并解压到自己的用户目录。在终端输入 `cd `（末尾保留空格），将解压后的项目文件夹拖入终端，再按回车。该目录应包含 `pyproject.toml`。
3. 在项目目录依次执行：

```bash
python3 -m venv .venv-gui
.venv-gui/bin/python -m pip install --upgrade pip
.venv-gui/bin/python -m pip install '.[gui]'
.venv-gui/bin/python -m omsimod.gui
```

首次安装依赖需要联网。以后启动时，进入同一项目目录，只需执行最后一条命令；使用期间保留该终端窗口。无需激活虚拟环境，也无需使用 `sudo`。

在“角色库与游戏”中选择自己的 OMSI 内容目录（包含 `Humans`、`Maps`、`Vehicles` 等资源的目录）。若需要通过本工具启动游戏，选择 OpenOMSI 应用包内的实际可执行文件；常见位置为 `/Applications/openOMSI.app/Contents/MacOS/openomsi`，以实际安装位置为准。Finder 中可右键应用，选择“显示包内容”。

也可以只使用命令行检查或转换模型。在完成上述安装后，于项目目录执行：

```bash
.venv-gui/bin/python -m omsimod inspect "/path/to/model.pmx"
.venv-gui/bin/python -m omsimod convert "/path/to/model.pmx" --output "/path/to/new-package" --name MyDriver --height 1.75
```

将示例路径替换为自己的路径；`1.75` 是示例网格高度（米），请按模型需要调整。输出目录必须尚不存在。命令行转换仅生成人物包，不会自动安装到游戏；自动安装和批量应用请使用图形界面。当前版本在不同 macOS、处理器及依赖组合上的兼容性仍需实机验证。

### 命令行与开发

命令行保留手动选择输出目录和高度的方式，不显示 GUI 阅读弹窗。运行前请自行阅读项目及模型许可。

```bash
python -m omsimod inspect "path/to/model.pmx"
```

### 司机动画与车辆识别限制

本工具负责转换人物模型，驾驶过程中的司机动作由 **OpenOMSI 自身的动画系统**生成。

根据目前查阅的 OpenOMSI 0.3.37 对应源码，司机系统包含以下动作及姿态适配：

- **坐姿适配**：调整坐姿、身体前倾和座位前后位置，使手臂尽量够到方向盘。
- **转向动作**：双手跟随方向盘转动，支持松手、重新握持和交替调整握持位置。
- **手部握持**：根据方向盘或挡杆的位置调整手掌朝向和手指弯曲；并非完整的 MMD 独立手指动画。
- **换挡动作**：识别挡杆后，由对应一侧的手伸向挡杆、跟随移动，再返回方向盘；部分情况下会生成短暂的推拨动作。
- **停车搭手动作**：停车一段时间后，手可能离开方向盘并搭到识别出的挡杆上。
- **下半身坐姿适配**：调整腿部弯曲和脚部位置。当前检查到的司机代码没有根据油门、刹车、离合输入生成对应踩踏动作；离合输入可以参与触发换挡手部动作。

以上是对所查版本源码的概括，不代表每辆车都能完整实现，也不构成对后续版本的保证。目前没有在检查到的司机动作代码中发现专门操作转向灯、雨刷或仪表台按钮的手部动作。

源码参考（固定版本 `b5e4acc`）：[司机动作](https://github.com/openOMSI-org/openOMSI/blob/b5e4acc/crates/omsi-scene/src/driver.rs)、[方向盘与挡杆识别](https://github.com/openOMSI-org/openOMSI/blob/b5e4acc/crates/omsi-scene/src/driver/rig.rs)。

#### 为什么不同车辆的动作不一样？

OpenOMSI 并不是单纯读取车辆预先制作好的司机动画，而是先识别车辆部件，再计算手部动作。其中，**挡杆识别依赖动画变量名、模型文件名中的关键词，并结合距离和可触及范围等条件**；方向盘则结合转向变量、旋转幅度和位置等信息识别。

因此，可能出现“识别不到”或“误识别”：

- **挡杆未被识别：** 在此前检查的 ПАЗ 3205R 车辆配置中，挡位可以正常切换，挡杆也正常移动，但司机的手不执行换挡动作。其挡杆文件名和动画变量名未命中所查版本的识别规则。
- **其他拨杆被误当成挡杆：** WG120FK 出现了司机右手向拨杆方向单独伸出的现象。源码与车辆配置分析显示，右侧雨刷拨杆变量 `cockpit_wischer_drehschalter` 包含挡杆识别关键词 `schalt`，存在被误认成挡杆的可能。停车搭手逻辑也可能因此产生类似操作拨杆的动作。**这是目前的分析推断，尚未通过运行时识别记录或对照实验完全确认，不能据此认定游戏已实现专门的拨转向灯动画。**
- **空挡时手臂异常：** 曾观察到挂 N 挡时手臂异常摆动，根因尚未定位，可能涉及游戏动作逻辑、车辆配置或转换模型适配。

出现上述现象不一定是 PMX 转换错误。请先恢复原版司机，在相同车辆、挡位和操作条件下对比，并向本项目提交结果，帮助区分模型适配问题与游戏、车辆配置问题。
