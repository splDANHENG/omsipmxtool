重建程序 / Rebuild the application (PowerShell, Windows x64)
Install CPython 3.14.0 x64 from python.org, extract the project source, then:
  py -3.14 -m venv .venv-gui
  .\.venv-gui\Scripts\python.exe -m pip install -r requirements-release.txt
  .\.venv-gui\Scripts\python.exe -m unittest discover -s tests
  .\.venv-gui\Scripts\python.exe scripts/build_gui.py
  .\.venv-gui\Scripts\python.exe scripts/fetch_release_sources.py
  .\.venv-gui\Scripts\python.exe scripts/package_windows.py
The output folder is dist/omsipmxtool. These instructions produce a functional
rebuild; byte-for-byte reproduction of the upstream wheels is not claimed.
Upstream archives include their build scripts and instructions. Qt uses shared
MSVC 2022 x64 release libraries. Build a compatible Qt with CMake/Ninja and the
Windows SDK, using qtbase/configure.bat -opensource -confirm-license -shared
-release -nomake examples -nomake tests -prefix <your-prefix>, then cmake --build .
and cmake --install . from a separate build directory. See qtbase/README.md.
For bindings, see pyside-setup/README.md and sources/pyside6/doc/building_from_source/
in the supplied archive; use the matching Qt 6.12.0, x64 MSVC and Python ABI.
Official build details: https://doc.qt.io/qtforpython-6/building_from_source/index.html

替换库 / Replace or modify the libraries
You may modify the LGPL libraries and reverse engineer the combined work to debug
those modifications. This project imposes no prohibition on those activities.
Close the application, back up the complete extracted folder, and replace the
interface-compatible Qt DLLs/plugins under _internal/PySide6, PySide6 .pyd files
and pyside6.abi3.dll there, and the Shiboken files under _internal/shiboken6.
Preserve filenames, architecture, dependent libraries and ABI compatibility.
No signature or hash enforcement prevents loading your replacements. Qt plugins
must match the Qt build. Restart the EXE to use the replacement libraries.
If the Python wrappers also change, install your built wheels into the build
environment and run scripts/build_gui.py again to regenerate the frozen archive.
The complete application source and build hooks are supplied for this purpose.
No installation key, vendor account or hardware lock is required.
